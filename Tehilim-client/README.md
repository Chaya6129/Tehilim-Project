# חלוקת תהילים – לקוח React

לקוח Web למערכת חלוקת פרקי תהילים, מול שרת ASP.NET Core.
Vite, React 18, TypeScript (strict), React Router, TanStack Query ו-CSS Modules.

## דרישות מוקדמות

- **Node.js 20 LTS** (מינימום 18.18). בדיקה: `node -v`
- השרת רץ בכתובת `https://localhost:7245`
- .NET SDK, לצורך אישור תעודת הפיתוח (ראו בהמשך)

## התקנה והרצה

```bash
npm install
npm run dev
```

האפליקציה נפתחת בכתובת **http://localhost:5173**.

הפורט קבוע (`strictPort: true`), כי השרת מאשר CORS רק לכתובת הזו. אם הפורט תפוס, Vite יעצור עם שגיאה ולא יעבור לפורט אחר. במקרה כזה סגרו את התהליך שתופס אותו.
חשוב לגלוש דרך `localhost` ולא דרך `127.0.0.1`. מבחינת CORS אלה שני מקורות שונים.

פקודות נוספות:

| פקודה | פעולה |
|---|---|
| `npm run build` | בדיקת טיפוסים ובנייה לתיקיית `dist` |
| `npm run typecheck` | בדיקת טיפוסים בלבד |
| `npm run preview` | הרצת הבנייה מקומית, על אותו פורט |

## משתני סביבה

| משתנה | ערך בפיתוח |
|---|---|
| `VITE_API_URL` | `https://localhost:7245` |

הערך נקרא מ-`.env.development`. לסביבות אחרות העתיקו את `.env.example` ועדכנו אותו.

## פתרון תקלה נפוצה: תעודת HTTPS בפיתוח

אם כל הבקשות נכשלות עם ההודעה "לא ניתן להתחבר לשרת", הדפדפן כנראה חוסם את תעודת הפיתוח של השרת.

1. אישור התעודה במחשב (פעם אחת):
   ```bash
   dotnet dev-certs https --trust
   ```
2. פתחו פעם אחת בדפדפן את כתובת השרת, למשל https://localhost:7245/swagger, ואשרו את התעודה אם מופיעה אזהרה.
3. רעננו את האפליקציה.

אם התקלה נמשכת, ודאו שהשרת אכן רץ על הפורט 7245.

## מבנה הפרויקט

```
src/
  api/         apiClient המרכזי, פונקציה לכל endpoint, טיפוסים לפי swagger, מפתחות cache
  auth/        sessionStore, AuthProvider, פענוח JWT, ניתוב מוגן
  components/  רכיבי ממשק: רשת הפרקים, חלונות, טפסים, toast, עיטורים
  hooks/       hooks של TanStack Query, debounce, מצב הסינון ב-URL
  pages/       מסכי האפליקציה
  styles/      design tokens ועיצוב גלובלי
  utils/       מספור עברי, תאריכים, שגיאות ועוד
```

כל קריאה לשרת עוברת דרך `src/api/client.ts`. אף רכיב לא קורא ל-`fetch` ישירות.

## החלטות שהתקבלו

**חוזה ה-API**
- `swagger.json` הוא מקור האמת. שדה היעד הוא `goal`, `SortBy` נשלח כמספר (0 או 1), וסטטוסים של ספר ופרק מגיעים כמחרוזות.
- תאריך שמגיע בלי סימון אזור זמן (למשל `DateTime` של .NET מסוג Unspecified) מתפרש כ-UTC. ההמרה לשעון המקומי נעשית בתצוגה בלבד.
- מזהה המשתמש נלקח מה-claim `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/nameidentifier` שב-JWT. אם הוא לא קיים, הלקוח בודק גם את `nameid` ואת `sub`, כי `JwtSecurityTokenHandler` ממפה כברירת מחדל את ה-claim הארוך ל-`nameid`.
- שמות שדות בשגיאות ולידציה (`Goal`, `$.goal`) מנורמלים ל-camelCase, כדי שההודעות יוצגו ליד השדה הנכון.

**התחברות**
- ה-token נשמר ב-localStorage ומסונכרן בין לשוניות. ההתנתקות האוטומטית מתוזמנת לפי `expiresAtUtc`.
- תגובת 401 לבקשה שנשלחה עם token מנתקת את המשתמש. תגובת 401 במסך ההתחברות מוצגת כ"אימייל או סיסמה שגויים".
- הסתרת פעולות לפי תפקיד או בעלות נועדה לנוחות בלבד. ההרשאה נאכפת בשרת.

**רשימת הספרים**
- 12 ספרים בעמוד. הדפדוף, החיפוש, הקטגוריה והמיון נשמרים ב-URL (`page`, `q`, `category`, `sort`), כך שאפשר לשתף קישור לתוצאות.
- ארבע אפשרויות מיון: החדשים ביותר, הוותיקים ביותר, הכי הרבה פרקים פנויים, וקרובים להשלמה.
- החיפוש נשלח לשרת 350 מילישניות אחרי סיום ההקלדה.

**מסך הספר**
- הפרקים מחולקים לחמשת הספרים שבספר תהילים (א–מא, מב–עב, עג–פט, צ–קו, קז–קנ).
- מספור עברי: אות בודדת נכתבת בלי סימן (א, ב, י), וצירוף של כמה אותיות נכתב עם גרשיים (ט״ו, ט״ז, ק״נ).
- פנוי ותפוס נבדלים לא רק בצבע. פרק פנוי מוצג במסגרת עם התווית "פנוי", ופרק תפוס מוצג במילוי, עם סימן וי ושם הנוטל.
- הרשת מתרעננת כל 5 שניות כשהלשונית פעילה, וגם מיד כשהחלון חוזר לפוקוס. הרענון נעצר כשהספר הושלם.
- בתגובת 409 מוצגת ההודעה "הפרק נלקח זה עתה על ידי משתתף אחר, אנא בחר פרק אחר", והרשת מתרעננת מיד.
- הסימון "נלקח על ידך" מוצג רק לפרקים שנלקחו בביקור הנוכחי, כי השרת לא מחזיר את מזהה הנוטל.
- שם האורח אופציונלי. אם לא הוזן, הבקשה נשלחת בלי `guestName`.
- קישור השיתוף נבנה מהכתובת הנוכחית של האפליקציה: `/books/{id}`.

**תצוגה**
- תאריכי יצירה והשלמה מוצגים בלוח העברי (למשל ז׳ בחשוון תשפ״ז). שעת הנטילה של פרק מוצגת בשעון המקומי.
- כל האנימציות מכבדות את `prefers-reduced-motion`.
- אין קובץ `package-lock.json`. הוא ייווצר בהרצה הראשונה של `npm install`, ומומלץ לשמור אותו בגיט.
